Quiénes somos

Una consultora venezolana que decidió digitalizar su propia forma de trabajar.

Sociedad Civil Consultores TAF opera desde Barquisimeto, estado Lara, desde 2019. NEXUS-TAF nace del mismo diagnóstico que resolvemos para nuestros clientes: sin una plataforma propia, la información se fragmenta y el seguimiento se vuelve opaco.

Consultores TAF fue fundada por las licenciadas Rosana Ochoa y Leticia Cuevas a partir de su experiencia como docentes universitarias, detectando debilidades recurrentes en la gestión administrativa, contable y organizacional de pequeñas y medianas empresas venezolanas.

Hoy el equipo está conformado por 6 personas —2 socias directivas y 4 colaboradores fijos— además de especialistas contratados por honorarios profesionales cuando un proyecto de asesoría lo requiere.

Por qué existe NEXUS-TAF

Cuatro fricciones que frenaban el crecimiento de TAF.

Detectadas junto a la Dirección de Operaciones y la Presidencia de la empresa durante el levantamiento de información del proyecto.

01

Fragmentación

Sin plataforma centralizada, la información vive en silos y dificulta la colaboración entre ramas de consultoría.

02

Opacidad

Los clientes no tienen visibilidad en tiempo real del avance de su asesoría, lo que erosiona la confianza.

03

Ineficiencia

No existe un mecanismo automatizado para equilibrar la carga de trabajo según disponibilidad y especialidad.

04

Desconexión técnica

Herramientas heterogéneas impiden estandarizar procesos bajo un marco de trabajo ágil común.

La plataforma, módulo por módulo

Cinco paneles, un solo flujo de trabajo.

De la autenticación al reporte ejecutivo: así se ve cada panel que consultores, clientes y directiva usan a diario dentro de NEXUS-TAF.

Sprint 1 · Módulo de Seguridad

Login con verificación de doble factor

El acceso exige correo y contraseña válidos; superada esa capa, la interfaz solicita un código TOTP de 6 dígitos enviado por correo antes de abrir cualquier módulo.

  • Contraseñas resguardadas con hash y control de intentos fallidos
  • Sesión emitida por JWT con expiración corta
  • Bloqueo automático tras intentos fallidos repetidos

Diseño técnico

Arquitectura, base de datos y requisitos del proyecto.

La documentación técnica que sostiene NEXUS-TAF, resumida en tres vistas: cómo está construido, dónde vive cada dato y qué debía cumplir desde el primer sprint.

Stack tecnológico

FrontendReact / Angular

Interfaces reactivas, modulares y de alto rendimiento por panel.

BackendNode.js (NestJS) / Django

Manejo eficiente de concurrencia y escalabilidad de servicios.

Base de datosPostgreSQL + MongoDB

SQL para integridad financiera; NoSQL para archivos, tareas y logs.

InfraestructuraDocker & Kubernetes

Portabilidad y despliegue continuo (CI/CD) de cada microservicio.

PatrónMicroservicios / MVC

Mantenimiento independiente por cada rama de consultoría.

Principios de diseño del webservice

Seguridad

HTTPS, validación de tokens JWT y control de acceso por roles en cada endpoint.

Escalabilidad

Separación por microservicios y desacoplamiento funcional entre módulos.

Interoperabilidad

Respuestas en JSON y estructura REST uniforme para integraciones de terceros.

Mantenibilidad

Código modular, endpoints bien definidos y documentación técnica viva.

Flujo de una solicitud

01

El usuario interactúa con el frontend y dispara una solicitud.

02

El frontend envía la petición al backend vía API REST.

03

El backend valida autenticación, autorización y reglas de negocio.

04

El backend consulta PostgreSQL o MongoDB según el dominio del dato.

05

El sistema responde en JSON y el frontend actualiza la interfaz.

La base de datos se diseñó bajo un enfoque híbrido: un motor relacional para lo crítico y transaccional, y un motor documental para lo operativo y flexible. Ningún dato financiero vive fuera de PostgreSQL; ningún tablero ágil depende de un esquema rígido.

Limitantes no funcionales del sistema

NFR·01
Seguridad y privacidad

Cifrado de extremo a extremo y autenticación multifactor por la sensibilidad legal de los datos de cada cliente.

NFR·02
Interoperabilidad

Integración con herramientas de terceros —bancarias, gubernamentales, documentales— vía arquitectura API REST.

NFR·03
Escalabilidad crítica

Crecimiento modular por microservicios que permite sumar ramas de consultoría sin afectar las existentes.

NFR·04
Consistencia híbrida

Convivencia de transacciones rígidas (finanzas) con esquemas flexibles (documentos técnicos) vía SQL + NoSQL.
